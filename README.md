# Demonstration
Пример 1 из моих последних плагинов для серверного ядра Paper игры Minecraft.
Данный плагин должен был создавать различные независимые кастомные события на сервере, поэтому плагин был разработан на архитектуре, реализовывающей принцип полиморфизма.
Оригинальный плагин был гораздо больше и включал десяток различных модулей. Поскольку все они работают по 1 концепции, для простоты понимания структуры кода я оставил тройку реальных модулей, реализовывающих некоторые функции.

Концепция данной экспериментальной архитектуры - реализовать управляющую систему и подключаемые "модули".
По задумке, все "модули" реализовывают 1 общий абстрактный класс BaseModule, а управляющая система работает с ними всеми единообразно, как с объектами этого самого абстрактного класса.
Все настройки, действия и реакции на глобальные события модули выполняют внутри себя, в рамках 1 файла. Управляющая система же выполняет минимальный функционал регистрации модулей, предоставления доступа к ним и управления в случае необходимости (например для перезагрузки)

Для простоты понимания проекта рекомендую изучать его в таком порядке:
Demonstration.java->demonstration.core.*->demonstration.modules.*->ZabvenieCommand.java

Данную систему я реализовывал впервые, и во время работы с ней заметил 2 существенных недочета, которые в будущем буду исправлять:
1). Идея о том, что вся логика модуля должна будет реализовываться в рамках 1 файла оказалась неэффективной. В некоторых особых случаях код модуля разрастался до 1000+ строк с примерно общим для модулей функционалом, что усложняло дальнейший дебаггинг и обновление модуля.
2). Заранее не продуманная система хранения общих данных. Во время работы появилась идея позволить 2 модулям знать о результатах своих действий, и как временное решение были использованы JSON файлы, что, очевидно, не самая лучшая идея.
